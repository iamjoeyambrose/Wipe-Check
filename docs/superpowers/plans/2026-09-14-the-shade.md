# The Shade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** A secret melee hero (the Shade) unlocked by lighting a dark torch on stage 3 and freeing the prisoner behind the hidden wall it opens; playable in the DPS seat solo and online.

**Architecture:** A class layer on the DPS seat (`h.cls` = `'ranger'|'rogue'`, `CLASSES` table in config); Ranger-specific code branches on it. The secret lives in `src/secret.js` (torch, door, alcove floor rule, prisoner, unlock) and is mirrored to guests through three header bytes and one class byte per hero in the snapshot.

**Tech Stack:** Canvas 2D, ES modules, the custom bundler (unique top-level names, plain named imports only), Playwright scratch tests, local PeerJS broker for online checks.

**Spec:** `docs/superpowers/specs/2026-09-14-the-shade-design.md`

## Global Constraints

- Bundled modules share one scope: no two files may declare the same top-level name; no `import * as`, no `as` aliasing.
- No camera motion on hits (no shake/kick/zoom). Ever.
- Solo behaviour for a Ranger party must not change; all existing scratch suites (`verify bullets rez relics zaxis steady objective stage5 ach fragdrop net mp lobby`) must pass on `dist/` and `index.html`.
- Guests never simulate; anything a guest sees comes from the snapshot, `slow`, or an event.
